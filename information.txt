VolatilisOS — GUI Edition
=========================

This page introduces the graphical edition of VolatilisOS. For downloads,
screenshots, published checksums and the newest public documentation, start
with README.md in this repository.

Release line: VolatilisOS 2.2 Beta, "Navy Horizon"
ISO build: 24 November 2026, from source-code main at
549e6d454157675664eeb416975f50d8742b29f4. See README.md, section
"What's new in the 24 November 2026 build".

NOTE: The downloadable ISO here is an uploaded snapshot. The source tree is
developed separately and can be newer than the uploaded binary.

What it is
----------

VolatilisOS is an independently developed experimental 32-bit x86 operating
system. Its GUI edition boots a native windowed desktop. The separate CLI
edition boots its own text-first kernel. Selected core, filesystem and
userspace code is shared between the editions; they are not a single kernel
with a simple graphical toggle.

The graphical desktop provides moveable windows, taskbar and launcher,
Settings, Files, Terminal, Text Editor, System Monitor, media viewers,
calendar/clock utilities and other built-in tools. Some additional programs
are delivered through VPK packages or ports rather than being written into
the kernel as built-in applications. The source has a NetSurf browser port
and DoomGeneric/Freedoom integration; their runtime features and packaging
must be checked against the particular ISO being used.

VolatilisOS began as a solo hobby operating-system project. The goal remains
to learn and experiment with the boot process, drivers, memory management,
filesystems, user applications and graphical desktops.

What changed since older GUI documentation
------------------------------------------

- The original documentation described one giant src/desktop.c and a
  640x480, 16-colour-only interface. The present source is organized into
  kernel/core, kernel/services, drivers, graphics, filesystem, networking,
  libraries, userspace, installer and vscript.
- The desktop includes newer renderers, compositing, fonts and
  graphics-device abstractions. Supported sizes/colours depend on the boot
  environment; do not assume every real graphics card is supported.
- Networking includes Ethernet, IPv4/IPv6 and TLS development. Wi-Fi user
  interface and driver groundwork exist, but the current hardware-support
  path cannot scan or join a wireless network.
- VFS and storage work extends beyond the older simple filesystem; some
  external filesystem formats are read-only by design.
- The GUI is not completely self-contained: third-party ports, packages,
  fonts and other dependencies retain their respective upstream licenses.
- The master menu offers graphical and keyboard-only installation. The CLI
  frontend is also available as "vos-install --cli" and uses the established
  checked installer backend.
- MOD7 is the factory icon default. Vista, Modern VOS, Native and Android
  themes are selectable in Settings. The imported Windows-derived themes are
  identified as third-party artwork, not original VolatilisOS artwork.

Safety and compatibility
------------------------

The current source has BIOS installer and QEMU verification paths, but this
is not a certification to install to real-world disks. Use new disposable
virtual disks for installation experiments; never risk a disk that stores
personal data. UEFI live boot has OVMF development evidence, but UEFI
installation is gated off and Secure Boot is unsupported.

The supported development guest profile is 32-bit x86 with one CPU. SMP,
arbitrary hardware support and full Linux/Windows application compatibility
are not claimed. Real-machine BIOS installed boot is still subject to a
documented retest in the development release gate.

How to try the published GUI ISO
--------------------------------

Install QEMU first. In a directory containing volatilis-gui.iso:

    qemu-system-i386 -m 1024 -cdrom volatilis-gui.iso -boot d

For the CLI edition:

    qemu-system-i386 -m 512 -cdrom volatilis-cli.iso -boot d

For the master selection menu, unpack volatilis-master.iso.zip and boot
volatilis.iso with QEMU. These commands do not attach a host physical disk.

Source code and build instructions
----------------------------------

This public repository primarily provides release images and screenshots.
The current authoritative source lives in a separate *private* repository:

    https://github.com/chanatun-volatilis/VolatilisOS-source-code

If you have access, build commands in that source checkout include:

    make toolchain
    make kernels
    make iso
    make run
    make check-iso QA_TIMEOUT=90

These commands do NOT run from the public image-only repository.
They are for developers with the private source and an appropriate toolchain.
For current Kali/Debian/Ubuntu source builds, first run
    ./build.sh --setup-linux
and then ./build.sh for subsequent ISO builds. The full ISO needs the real
i686-elf SDK toolchain; host GCC -m32 alone is not enough.
See docs/THIRD_PARTY_SOFTWARE.md for the native DoomGeneric/Freedoom port.
Source tests should distinguish PASS, FAILED, BLOCKED and NOT TESTED; QEMU
success does not imply physical-hardware certification.
